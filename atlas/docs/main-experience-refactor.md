# 《诸象》主体验重构文档

> 目标：把《诸象》从“多占法工具箱”重构为“全球文明象征系统对照台”。

当前项目已经拥有较丰富的方法清单、文化元数据、单方法页面和同题多算能力，但主体验仍然容易把用户引导到“选择一种占法，然后获得一次结果”。这与产品核心愿景之间存在错位：

> 核心不是“告诉你命运是什么”，而是把不同文明的象征系统放在同一张桌上，让用户体会每种文化如何提问、如何理解因果、如何处理不确定性。

因此，本次重构的重点不是继续增加更多占法，而是重构用户进入问题、理解差异、阅读报告、学习体系的方式。

---

## 1. 核心判断

### 1.1 当前模式的问题

当前产品的实际体验更接近：

```text
用户有困惑
  -> 选择一个占法
  -> 输入资料或抽取符号
  -> 获得该占法结果
  -> 可选地查看其他体系
```

这个模式的优点是功能清楚、实现直接、用户容易理解。但它也带来几个根本问题：

1. **方法压过问题**
   用户首先面对的是“八字、塔罗、周易、奇门、符文”等方法入口，而不是自己的问题。产品会自然滑向“工具集合”。

2. **结果压过文化差异**
   报告页虽然有共识和分歧，但用户读到的仍主要是“各体系怎么说”。他们不一定能理解“为什么这些体系会这样说”。

3. **占法被统一成同一种交互**
   很多方法会被迫适配同一套输入、按钮、报告结构。结果是每种传统的气质被削弱。

4. **新增方法只会增加广度，不会增加主体验深度**
   即使继续加入 Saju、宿曜、Horary、Prashna、Ifa、Tzolk'in，如果主流程仍是方法列表，产品仍然不够独特。

5. **“文明对照”的价值没有在第一屏发生**
   README 和 PRD 中的定位很清楚，但用户进入产品后，仍需要自己发现这个价值。

### 1.2 重构后的核心体验

重构后的主体验应该变成：

```text
用户带着一个真实问题进入
  -> 系统识别问题类型和不确定性结构
  -> 将同一个问题翻译成不同文明可理解的问题格式
  -> 用户选择要放上桌的象征系统
  -> 各系统按自身方式生成证据、判断和边界
  -> 报告展示“提问方式 / 因果模型 / 不确定性处理”的差异
  -> 用户得到现实行动建议，同时理解文化差异
```

一句话：

**用户不是来选择占法，而是把自己的问题放到不同文明的认知桌面上。**

## 2. 产品北极星

### 2.1 新的主体验命题

《诸象》的主体验应该回答：

> 当一个人面对不确定性时，不同文明会如何把这个问题变成可理解、可解释、可行动的形式？

这句话比“同题多算”更准确。

“同题多算”强调多个结果并列；“文明对照台”强调多个认知方式并列。

### 2.2 三个体验支柱

#### 支柱一：如何提问

每种传统都有自己的问题格式。

例如“我适合离职吗？”在不同体系中不应该被当作同一句问题处理：

| 体系 | 它真正关心的问题 |
|------|------------------|
| 周易 | 此时此位是否宜变？变的条件是否成熟？ |
| 六爻 | 此事成败如何？用神旺衰如何？阻力在哪里？ |
| 八字 | 当前大运流年是否触发职业结构变化？ |
| 西洋占星 | 职业宫、行运与个人动力是否出现调整压力？ |
| 塔罗 | 用户在选择中看见和没看见的心理动力是什么？ |
| 奇门 | 此行动的时机、方位、资源与局势是否配合？ |

这一步必须前置。否则用户只会看到“不同占法给了不同答案”，看不到“不同体系一开始就不是在问同一个问题”。

#### 支柱二：如何理解因果

不同传统有不同的因果想象。

| 因果模型 | 代表体系 | 说明 |
|----------|----------|------|
| 结构因果 | 八字、紫微、Saju | 出生时刻形成长期结构，后续周期触发结构变化 |
| 时位因果 | 周易、奇门、六爻 | 当前处境、位置、时机与行动关系决定判断 |
| 象征投射 | 塔罗、神谕卡、水晶凝视 | 外部符号让内在心理、情境关系显形 |
| 天体周期 | 西洋占星、吠陀占星 | 天体位置与周期被视为人生节律的象征框架 |
| 礼俗确认 | 签诗、杯筊、Istikhara | 通过仪式、劝诫或确认机制帮助行动定心 |
| 民俗联想 | 咖啡渣、梦占、相术 | 从日常痕迹、梦境、身体观察进入象征解释 |

报告不应只输出“结论”，还要解释结论来自哪一种因果观。

#### 支柱三：如何处理不确定性

每种传统并不以同一种方式处理不确定性。

| 不确定性处理方式 | 代表体系 | 典型输出 |
|------------------|----------|----------|
| 趋势判断 | 八字、占星 | 某阶段更容易发生什么 |
| 时机判断 | 周易、奇门、六爻 | 现在是否宜动、何时更稳 |
| 心理显影 | 塔罗、梦、神谕卡 | 你正在回避什么、需要看见什么 |
| 是非确认 | 杯筊 | 可以、不可、未明、需重问 |
| 劝诫修辞 | 签诗 | 宜守、宜缓、宜修德、宜等待 |
| 叙事拼接 | Lenormand、咖啡渣 | 事件线索如何组合成近期故事 |

这会让用户明白：不同体系给出的“确定性浓度”不同，不能把所有输出都当作同一种预测。

## 3. 新信息架构

### 3.1 当前信息架构

```text
今日
问事
占法
梦境
资料馆
个人档案
设置
```

这套架构的问题是：“占法”仍是强中心，“问事”只是其中一个功能。

### 3.2 建议信息架构

```text
今日之问
对照台
象征系统
资料馆
个人档案
设置
```

#### 今日之问

首页。提供当天的反思入口、问题模板和轻量对照，而不是单纯今日运势。

核心任务：

- 让用户带着问题进入
- 推荐适合的文明视角
- 展示一个小型对照样例
- 引导到完整“对照台”

#### 对照台

主功能。替代当前“Ask / 同题多算”。

核心任务：

- 输入自然语言问题
- 识别问题类型
- 生成跨文明问题翻译
- 选择系统组合
- 生成对照报告

#### 象征系统

替代当前“占法 / Methods”。

核心任务：

- 按文明、问题类型、因果模型、不确定性处理方式浏览方法
- 解释每种系统的提问方式、证据习惯和边界
- 进入单方法体验

#### 资料馆

保留古籍、文本、引用、学习内容。

核心任务：

- 支撑证据可信度
- 展示原典、翻译、注释和版权状态
- 作为研究与学习入口

#### 个人档案

保留多体系画像，但它不应只是命盘集合，而应回答：

- 哪些体系最适合解释你的长期问题？
- 哪些体系只适合短期反思？
- 你的问题常落在哪些文明视角中？

## 4. 主流程设计

### 4.1 对照台完整流程

```text
Step 1. 写下问题
Step 2. 识别问题类型
Step 3. 翻译成多种传统的问题格式
Step 4. 选择放上桌的象征系统
Step 5. 补充必要资料
Step 6. 生成对照报告
Step 7. 阅读三层报告
Step 8. 继续追问或保存
```

### 4.2 Step 1：写下问题

用户输入自然语言：

```text
我最近想离职，但又怕现在不是好时机。我该怎么判断？
```

界面不应立即要求用户选择“八字 / 塔罗 / 周易”。先让问题完整出现。

输入区可以提供四类问题模板：

- 选择：我该不该做某事？
- 关系：我和某人的关系卡在哪里？
- 阶段：我现在处在什么人生节奏？
- 梦境：这个梦为什么反复出现？

### 4.3 Step 2：识别问题类型

系统分析这个问题属于什么不确定性：

```text
问题类型：职业选择 / 行动时机 / 风险评估
时间尺度：近 1-6 个月
需要资料：出生资料可增强长期周期判断；不提供也可用问事型系统
敏感边界：涉及财务与职业决策，输出需避免确定性承诺
```

这一步可以先用规则实现，不必一开始依赖 LLM。

### 4.4 Step 3：问题翻译器

这是重构的核心组件。

界面展示：

```text
同一个问题，可以被不同传统这样理解：

周易
此时是否宜变？变动需要满足什么条件？

塔罗
我在离职选择中真正害怕和期待的是什么？

八字
当前大运流年是否触发事业结构调整？

西洋占星
近期事业宫、责任主题和自我方向是否受到行运触发？

奇门
如果采取行动，时机、方向、资源和阻力如何分布？
```

用户可以选择：

- 使用推荐组合
- 偏向长期结构
- 偏向短期行动
- 偏向心理反思
- 自定义系统

### 4.5 Step 4：选择系统组合

选择不应只显示方法名，还要显示“为什么适合这个问题”。

例如：

```text
推荐组合：周易 + 塔罗 + 八字 + 西洋占星

周易：适合判断此时是否宜变
塔罗：适合看见选择背后的心理动力
八字：适合观察职业结构与长期周期
西洋占星：适合观察近期压力和身份转向
```

不推荐的系统也可以出现，但要解释原因：

```text
杯筊：更适合清晰的是/否请示，不适合复杂职业规划。
咖啡渣：更适合近期氛围和生活线索，不适合长期职业结构。
```

这会让“边界”成为产品质感的一部分。

### 4.6 Step 5：补充资料

根据所选系统动态要求资料。

| 系统 | 必需资料 | 可选资料 |
|------|----------|----------|
| 八字 | 出生日期、时间、地点 | 性别、当前城市 |
| 西洋占星 | 出生日期、时间、地点 | 当前所在地 |
| 塔罗 | 问题文本 | 牌阵偏好 |
| 周易 | 问题文本、起卦方式 | 动爻说明 |
| 奇门 | 问题文本、当前时间 | 地点、方位 |
| 梦占 | 梦境文本 | 醒后情绪、重复意象 |

如果资料不完整，系统不应阻断所有流程，而应说明影响：

```text
缺少出生时间：八字和占星只能提供粗略结构，不能精确判断宫位或时柱。
```

### 4.7 Step 6：生成对照报告

报告生成不应只有一个综合 prompt，而应遵守分层结构：

1. 每个系统先按自己的方法生成结果
2. 每个系统输出自身的提问格式、证据、因果模型和边界
3. 聚合层只负责比较，不强行统一结论
4. 行动建议必须明确哪些来自共识，哪些来自单一体系

## 5. 报告结构重构

### 5.1 当前报告结构

当前报告大致是：

```text
结论摘要
共识
分歧
各体系解读
古籍依据
行动建议
风险提醒
```

这个结构可保留，但需要前置“文明认知层”。

### 5.2 新报告结构

建议结构：

```text
1. 问题总览
2. 同一个问题如何被翻译
3. 总体共识
4. 关键分歧
5. 三层对照表
   - 如何提问
   - 如何理解因果
   - 如何处理不确定性
6. 各系统详细解读
7. 原典与证据
8. 行动建议
9. 边界与风险
10. 可继续追问的问题
```

### 5.3 报告首屏

首屏不应该直接给“答案”，而应该先展示问题如何被摆上桌。

示例：

```text
你的问题
“我最近想离职，但又怕现在不是好时机。”

这不是一个单纯的“会不会成功”问题。
它同时包含：职业结构、行动时机、心理安全感、资源准备。

本次放上桌的系统：
周易：看时位与变动条件
塔罗：看心理动力与盲点
八字：看长期职业结构与阶段触发
西洋占星：看近期压力、责任和身份转向
```

### 5.4 三层对照表

这是新报告的核心视觉结构。

```text
┌──────────┬──────────────┬──────────────┬──────────────┐
│ 体系     │ 如何提问      │ 因果模型      │ 不确定性处理  │
├──────────┼──────────────┼──────────────┼──────────────┤
│ 周易     │ 此时是否宜变  │ 时位与阴阳变化│ 宜动/宜守      │
│ 塔罗     │ 内在动力如何  │ 象征投射      │ 心理显影       │
│ 八字     │ 周期是否触发  │ 结构与运势    │ 趋势判断       │
│ 西占     │ 行运触发什么  │ 天体周期      │ 阶段压力       │
└──────────┴──────────────┴──────────────┴──────────────┘
```

在移动端可改为横向卡片：

```text
周易
问法：此时是否宜变？
因果：时位、阴阳、动爻
不确定性：给出宜动/宜守的条件
```

### 5.5 共识与分歧的表达方式

共识不要写成“多数体系认为”，而要解释共识来自什么层面。

弱表达：

```text
多数体系认为你可以准备换工作，但不宜冲动。
```

强表达：

```text
共识出现在“行动节奏”层面，而不是“结果保证”层面：
周易强调变动需要条件成熟，塔罗显示你仍在安全感和自由之间拉扯，八字与西占都提示当前阶段确有职业结构调整信号。因此结论不是“应该立刻离职”，而是“可以开始准备有缓冲的转换”。
```

分歧也不要只是列冲突，要解释冲突来自方法差异：

```text
分歧主要来自时间尺度：
塔罗更关注你当前心理状态，因此看到犹豫和拉扯；
八字更关注长期结构，因此更容易把这段时间看作阶段转换；
周易则要求回到“此时是否具备行动条件”。
```

## 6. 页面级改造

### 6.1 Today 页面

当前 `TodayPage` 更像每日简报。建议改成“今日之问”。

#### 目标

让用户每天进入时，第一眼看到的是一个可反思的问题，而不是被动接收运势。

#### 建议模块

1. 今日之问
   - 一个当天可思考的问题
   - 可一键放入对照台

2. 今日文明视角
   - 今天推荐一个传统如何看待“不确定性”
   - 例如“周易：先问时位，再问吉凶”

3. 快速对照
   - 同一个小问题给出两个体系的不同问法

4. 继续上次的桌面
   - 恢复最近一次对照报告或草稿

#### 示例首屏

```text
今日之问
“你现在真正想改变的，是外部处境，还是自己在处境中的位置？”

放上桌：
周易会问：此时此位是否宜变？
塔罗会问：你在改变中害怕失去什么？
八字会问：这是否是阶段节律的触发？
```

### 6.2 Ask 页面 -> 对照台

当前 `AskPage` 应重命名或概念升级为 `WorkbenchPage` / `TablePage` / `ComparePage`。

#### 核心组件

1. `QuestionComposer`
   - 输入自然语言问题
   - 提供问题模板

2. `QuestionInterpreter`
   - 显示问题类型、时间尺度、敏感边界

3. `QuestionTranslationPanel`
   - 展示不同系统的问题翻译

4. `SystemSelectionTable`
   - 推荐组合和自定义选择

5. `RequiredInputsPanel`
   - 根据所选系统收集资料

6. `GenerateComparativeReportButton`

#### 当前 `AskComposer` 的问题

它现在混合了：

- 问题输入
- 模板选择
- 体系选择
- 提交按钮

这使得“同题多算”无法展开为更丰富的认知流程。建议拆分。

### 6.3 Methods 页面 -> 象征系统

当前标题“选择一种占法”需要改掉。

新的页面目标不是让用户挑工具，而是让用户理解系统之间的分类。

#### 新分组方式

1. 按文明
   - 东亚术数与民俗
   - 南亚星占与问事
   - 欧洲卡牌、星占与地占
   - 中东与地中海民俗
   - 现代心理与新灵性

2. 按问题类型
   - 长期人生结构
   - 具体事件成败
   - 行动时机与策略
   - 关系与心理动力
   - 梦境与意象
   - 空间与方位

3. 按因果模型
   - 出生结构
   - 天体周期
   - 时位变化
   - 抽取象征
   - 礼俗确认
   - 观察与痕迹

4. 按不确定性处理
   - 趋势
   - 应期
   - 劝诫
   - 确认
   - 心理显影
   - 叙事线索

#### 方法卡片内容

每张卡不应只显示 subtitle 和 tags，而应显示：

```text
八字 / Four Pillars

它如何提问：
这件事是否符合你的长期结构和阶段节律？

它如何理解因果：
出生时刻形成结构，大运流年触发变化。

它如何处理不确定性：
给出趋势和阶段倾向，不适合回答即时是非。

适合：
职业结构、关系角色、人生阶段

不适合：
今天几点做、某人是否马上回复
```

### 6.4 Reading 页面

报告页需要从“结果阅读器”变成“对照解释器”。

#### 新增组件

1. `QuestionFrameCard`
   - 展示原始问题、问题类型、时间尺度和边界

2. `QuestionTranslations`
   - 展示每个体系如何改写问题

3. `CulturalComparisonMatrix`
   - 三层对照表

4. `ConsensusExplainer`
   - 说明共识出现在哪个层面

## 8. 问题识别模型

### 8.1 问题维度

用户问题进入对照台后，系统应先识别这些维度：

```ts
type QuestionFrame = {
  rawText: string;
  domains: QuestionDomain[];
  timeHorizon: "immediate" | "weeks" | "months" | "year" | "life-stage" | "unknown";
  decisionPressure: "low" | "medium" | "high";
  sensitivity: Array<"medical" | "legal" | "financial" | "relationship" | "mental-health" | "none">;
  needsBirthData: boolean;
  needsLocation: boolean;
  recommendedMethodIds: string[];
  discouragedMethodIds: string[];
};
```

### 8.2 规则优先，不必一开始全靠 LLM

MVP 可以用规则：

- 包含“要不要、该不该、是否、能不能”：偏具体选择、是非、时机
- 包含“今年、未来一年、长期、事业方向”：偏长期结构
- 包含“他/她/关系/复合/分手”：偏关系
- 包含“梦见、反复梦、醒来”：偏梦境
- 包含“搬家、办公室、房间、方位”：偏空间
- 包含“焦虑、害怕、卡住、内耗”：偏心理状态

后续再用 LLM 做更细的语义分析。

### 8.3 推荐组合策略

推荐不是“默认全选”，而是按问题类型组合。

#### 职业变化

```text
周易 + 八字 + 西洋占星 + 塔罗
```

理由：

- 周易看时位与变动条件
- 八字看长期职业结构
- 西占看近期责任与身份转向
- 塔罗看心理动力和盲点

#### 具体事件成败

```text
六爻 + 奇门 + 周易 + Lenormand
```

理由：

- 六爻看用神与成败
- 奇门看局势、方位和策略
- 周易看变化条件
- Lenormand 看现实线索和事件叙事

#### 关系问题

```text
塔罗 + 西洋占星 + 八字缘合 + 周易
```

理由：

- 塔罗看情绪与互动
- 西占看关系模式
- 八字缘合看长期相处结构
- 周易看当前局面宜进宜退

#### 梦境问题

```text
占梦 + 荣格视角 + 中国梦占 + 神谕卡
```

理由：

- 占梦看民俗与文本传统
- 荣格视角看原型和心理材料
- 中国梦占看传统征兆语言
- 神谕卡用于温和反思

## 9. 交互细节

### 9.1 推荐系统不能装作中立

推荐组合必须说明“为什么推荐”和“为什么不推荐”。

示例：

```text
我们没有把杯筊放入推荐组合，因为你的问题包含长期职业规划，不是清晰的是/否请示。
```

这会让用户感受到产品有判断力。

### 9.2 用户可以保留文化偏好

设置中的文化视角应影响文案：

#### 文明对照

强调差异和比较。

```text
周易把它看作时位问题，塔罗把它看作心理动力问题。
```

#### 本土语境

减少外部类比，更多使用传统内部术语。

```text
本卦主当前之势，动爻主变机，宜先观其位正不正。
```

#### 跨文化入门

解释术语，降低门槛。

```text
“时位”可以理解为：此刻你的处境、位置和行动时机是否匹配。
```

#### 研究注释

强调来源、流变和不确定性。

```text
此解释采用现代周易占断框架，并非唯一传统断法。
```

### 9.3 不要把所有传统做成同一种 UI

主流程可以统一，但单方法细节要保留气质：

- 八字：结构表、周期轴、五行流动
- 周易：卦象、爻位、变卦路径
- 塔罗：图像牌阵、位置语义、叙事流
- 奇门：九宫盘、门星神、方向策略
- 签诗：签文、典故、劝诫、礼俗边界
- 咖啡渣：杯壁位置、图形联想、闲谈式叙事

统一的是“对照框架”，不是“占法皮肤”。

### 9.4 报告需要显示确定性浓度

每个体系结果可以带一个“确定性表达类型”，而不是数值概率。

```text
八字：趋势倾向
周易：条件判断
塔罗：心理镜像
杯筊：仪式确认
签诗：劝诫提示
```

避免使用“准确率 80%”这类伪科学表达。

## 10. MVP 范围

不要一口气重构所有方法。建议 V1 只做四个系统：


## 13. 风险与取舍

### 13.1 风险：流程变复杂

用户可能只想快速问一句，不想阅读方法论。

解决：

- 默认提供推荐组合
- 问题翻译卡片简洁展示
- 高级解释可折叠
- 保留“直接生成”按钮

### 13.2 风险：文化解释变成说教

如果每一步都解释“文明如何如何”，体验会变重。

解决：

- 首屏只给差异摘要
- 把学术解释放入展开层
- 用具体问题驱动解释，而不是先讲理论

### 13.3 风险：方法不够真实

如果底层演算薄弱，再好的对照结构也会显得空。

解决：

- V1 只选已有基础较好的四个体系
- 每个体系必须展示实际符号、结构或证据
- 模板化内容明确标注边界

### 13.4 风险：用户仍然追求“最准答案”

这是不可避免的用户心理。

解决：

- 不禁止用户寻找答案
- 但报告结构始终把“答案”放在“问题如何被理解”之后
- 行动建议区分共识、单一体系建议和现实判断

## 16. 最终判断

《诸象》现在不缺方法数量，缺的是一个能把所有方法组织起来的主隐喻和主流程。

过去的中心是：

```text
选择占法
```

新的中心应该是：

```text
把问题放上桌
```

过去的报告重点是：

```text
不同体系分别给出什么结果
```

新的报告重点应该是：

```text
不同文明如何把同一个不确定性转化为问题、证据、因果和行动
```

只要这个主体验立住，后续新增任何占法都会自然找到位置。否则，占法越多，产品越像目录；体系越全，体验越散。

本次重构的关键不是“少做功能”，而是先建立一个能容纳未来复杂度的桌面。
