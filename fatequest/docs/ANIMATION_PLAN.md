## 1. 原则：动画服务于「读」，不服务于「爽」

本作是文本旅行游戏，**不是动作游戏**。GDD 的四个乐趣支点里没有一条与打击感有关。

| 该做 | 不该做 |
|---|---|
| 让状态变化**被看见**（钱少了、图鉴+1） | 屏幕震动、镜头拉伸 |
| 让时间流逝**被感觉到**（行路、季节） | 华丽转场 |
| 让占卜的**仪式感**成立 | 华丽粒子秀 |
| 让文本**可读**（渐显、不闪） | 打字机音效轰炸 |

> **一条判准**：若某个动画让玩家读得更慢却没换来理解，就删掉它。

### 可访问性（与 `AUDIO_PLAN.md` A1 同级）

必须提供 **`reduce_motion`** 开关，且**第一版就有**：

| 开关状态 | 行为 |
|---|---|
| 关（默认） | 全部动效 |
| 开 | 位移/旋转/缩放 → 一律改为**淡入淡出**；粒子关闭；时长压到 50% |

Atlas 的 `methodExperiences.ts` 已有 `reducedMotionFallback: "fade" | "none"` 字段——**这个设计直接沿用**，移植时不要丢掉。

## 2. 五类动画

### 2.1 界面过渡（P2，最先做）

| 场景 | 动效 | 时长 |
|---|---|---|
| 书案 → 地图 | 羊皮纸展开（scale-y 0.9→1 + 淡入） | 400 ms |
| 事件弹出 | 自下淡入上移 12 px | 250 ms |
| 选项按钮 | 逐个错峰淡入 40 ms | 总 ≤200 ms |
| 面板切换 | 交叉淡入 | 180 ms |

**用 `Tween` 不用 `AnimationPlayer`**：这些是一次性、参数化的过渡，代码里写清楚比在编辑器里点更好维护，也便于 `reduce_motion` 统一改写。

### 2.2 地图动画（P2，价值最高）

素材已在仓库（`map-vellum-tile`、`map-fog-ink`、`map-city-*`、`map-route-*`），**接线即可看见巨大变化**。

| # | 动效 | 做法 | 备注 |
|---|---|---|---|
| M1 | **迷雾揭开** | `map-fog-ink` 作遮罩，`reveal_map` 触发局部溶解 | **最重要的一个**——GDD P2「地图来自询问」的视觉兑现 |
| M2 | **路线描画** | 沿路径逐段画出 `map-route-*` 笔触 | 行路时播放，长度对应天数 |
| M3 | 城塞小像浮现 | 情报级别 0→1 时淡入 `map-city-*` | 按文化取图 |
| M4 | 当前位置脉动 | 极缓呼吸（2 s 周期，±6% 透明度） | 唯一常驻动画，必须**极克制** |
| M5 | 风神头微动 | 极缓飘动 | 装饰，`reduce_motion` 下静止 |

**M1 与 M2 是本作动画的核心**。玩家 400 天旅程里最反复看到的就是「路一点点画出来、雾一点点退开」——这件事做好，整个游戏的质感就立住了。

### 2.3 占卜仪式（P3）

`archive/ATLAS_PORT.md` §1.3 记 Atlas 有**六式** motion 规范：

```
shuffle · orbit · ripple · flip · smoke · static
```

CSS 关键帧不能直接用于 Godot，但**曲线与时长可以照抄**——那是已经调过的参数，重画成 `Tween`/`AnimationPlayer` 即可。

| 占法 | 式 | 表现 |
|---|---|---|
| 易占 | `flip` | 三钱落案 → 六爻自下而上生成 → 变爻闪一次 |
| 签占 | `shuffle` | 签筒摇动 → 一签跳出 → 翻面显字 |
| 八字 | `static` | 四柱逐柱写出，无花哨 |

**仪式感来自节奏，不来自特效**：起卦要有「等待」——三钱落下之间留 300 ms，比任何粒子都更像占卜。

**与音频绑定**：签筒竹声、铜钱声由 `AUDIO_PLAN.md` §7.3 的程序化装饰提供，动画与声音同一时间轴触发。

### 2.4 状态反馈（P2）

| 事件 | 动效 |
|---|---|
| 金钱增减 | 数字滚动 + 飘字（`EffectResult.log_lines` 驱动） |
| 图鉴/贴纸获得 | 图标自事件面板飞向收藏入口 |
| 命运条变化 | 条形渐变，不跳变 |
| 天数推进 | 日期滚动 + 地图上行进推移 |

**全部由内核的 `EffectResult` 驱动**，不在 UI 层另写一套判断——`CODE_PLAN.md` §8 已定这条。

### 2.5 场景氛围（P2 末，可选）

场景背景加极缓视差与光晕呼吸。**优先级最低**，`reduce_motion` 下全关。

## 3. 技术选型

| 需求 | 方案 | 理由 |
|---|---|---|
| UI 过渡 | `Tween` | 参数化、易统一改写 |
| 地图迷雾 | **Shader**（遮罩 + 噪声溶解） | CPU 逐像素不可行 |
| 路线描画 | `Line2D` + 逐点推进，或 shader 的 `progress` uniform | 前者简单，先用前者 |
| 占卜六式 | `AnimationPlayer`（可视化调节奏） | 节奏需要反复微调 |
| 飘字/粒子 | `GPUParticles2D`，量极小 | — |

**不引入第三方动画插件**：本作需求简单，`Tween` + shader 足够，多一个依赖多一份 Godot 升级风险。

---

## 4. 与内核的边界

同 `AUDIO_PLAN.md` §9：

- `game/` 属 L2，**不得**被 `core/` 引用
- 动画**不得**写 `WorldState`
- 动画时长**不得**影响游戏逻辑时序——内核先算完，动画只是回放
- 动画随机（如雾的溶解噪声）走独立 fork，**不与玩法 RNG 共用**

> **最后一条特别重要**：如果动画的随机会消耗玩法随机流，那么「跳过动画」与「看完动画」会产生不同的世界。这是 `CODE_PLAN.md` §2.1 明令禁止的串流污染。

## 5. 实施顺序

| 序 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| **N0** | `reduce_motion` 开关 + 全局时长系数 | — | 开关能一键关掉所有动效 |
| **N1** | 地图素材接线（静态） | 素材已有 | 地图从彩色圆点变成舆图 |
| **N2** | M1 迷雾揭开 + M2 路线描画 | N1 | 走一段路能看见路被画出来 |
| N3 | 界面过渡（2.1） | — | 无生硬跳变 |
| N4 | 状态反馈（2.4） | — | 钱变了看得见 |
| N5 | 占卜六式（2.3） | P3 占卜接入 | 起卦有仪式感 |
| N6 | 场景氛围（2.5） | 场景图 | 可选 |

**N0 先做**，理由同 `AUDIO_PLAN.md` 的 A1：可访问性不是收尾工作。

**N1 是当前最划算的一步**——素材已经躺在仓库里，零采购成本，做完画面质变。

---

## 6. 不做什么

- **不做**角色行走动画（无角色立绘在地图上移动）
- **不做**战斗动效（本作无战斗）
- **不做**过场动画（CG）
- **不做**3D 任何东西
- **不做**通用动画框架（只服务本作）
