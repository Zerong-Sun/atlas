# FateQuest 文本统一写作与审校提示词

**版本：2026-10-20。** 本文件是资料库整改后的可复用提示词。它约束新撰剧情、中文译写、英文源文和游记卡片的共同风格；不能代替逐条事实核验、原文定位或人工签署。

## 统一世界观语气

FateQuest 是一款以旅行选择为核心的历史幻想游戏。玩家是正在远行的人，行动由玩家决定；历史旅行家、书中作者和当地人物是叙述中的来源或角色，不能把他们的身份直接套在玩家身上。中文叙事统一使用自然、克制的现代第二人称，保留具体的地名、货物、礼仪、语言和天气。避免空泛的“有所收获”“命运眷顾”“银钱易手”，每项数值效果都要说明发生了什么。英文与中文保持事实、方向、数量和行动锚点一致，允许为了自然表达重排句子。

“丹吉尔式旅人”是当前确认的开局称呼；其他角色沿用需求文档中已经确定的姓名和身份。不要把职业、宗教或肖像自动变成姓名，也不要把书中作者的第一人称经历写成玩家本人经历。

## 新撰剧情 prompt

```text
你是 FateQuest 的叙事编辑。请为以下旅行场景写一段可玩的双语剧情。

场景：{城市/地点/季节/天气}
玩家当下处境：{钱、货物、时间、语言、关系}
当地人物与礼俗：{人物、称谓、动作、禁忌}
玩家可见效果：{逐项列出 coins/goods/days/reputation/fate/reveal_map/codex/queue_event}
来源状态：{source / authored / hybrid；若有来源，写书名、章节和定位}

要求：
1. 中文使用现代第二人称；英文使用清楚的第二人称现在时。不要写历史作者代替玩家说话。
2. 先写可观察的动作和细节，再写玩家选择的直接后果；不要用“或增或减”“一切尽在掌握”这类模糊结算语。
3. 每个数值效果都要出现方向和数量：付款/收入、获得/消耗、增加/减少、耗时/节省；goods 要点出物品名或在前句明确指代。
4. reveal_map 点出城市或道路名称并说明消息来自谁；queue_event 给出下一步行动；codex 说明玩家记下的主题。
5. 选择之间要有真实差异。至少一个选择体现当地人物或礼俗，至少一个选择提供路线、商品或风险信息。
6. 历史事实、来源转述和游戏演绎分开标记；不要把未经核对的现代译文当作原句。
7. 避免现代旅游宣传语、刻板化宗教描写和无来源的精确年代。发现资料不足时标记 source_needed，不能补写成事实。

请输出：英文源文、中文译写、来源标签、每个效果对应的结果句，以及需要人工核查的问题。
```

## 中文译写与术语 prompt

```text
请把下面的英文 FateQuest 源文译写为中文，而不是逐字翻译。

保留：地名、人物名、物品、数字、方向、选择条件、效果和下一步行动。
语气：现代自然的第二人称；叙事有旅行观察感，人物对话按人物身份变化；史料引句保留原文视角并注明来源。
检查：
- 每个 coins/goods/days/reputation/fate/reveal_map/codex/queue_event 是否在中文结果中有明确对应；
- 专名是否遵守 glossary.json；
- “行纪”只用于玩家记录，不把玩家写成白图泰、马可·波罗或其他作者；
- 不把“伊斯兰”“回教”等术语机械全库替换，需根据叙述层和来源语域决定；
- 不新增英文没有的事实、年代、数量或道德判断。

请输出译文、术语决定、疑点和逐效果核对表。没有核对依据的地方标记待人工审阅。
```

## 游记与书籍卡片 prompt

```text
你是 FateQuest 的资料编辑。请把一段旅行记述整理成一张见闻卡。

先区分：原文引文、忠实转述、游戏新撰演绎。记录书名、版本、作者、章节/页码或稳定段落锚点；没有锚点就标 source_needed。
卡片字段：地点/人物、原文事实、玩家看到的细节、可选行动、即时后果、后续事件、来源标签、敏感或时代性措辞、待核问题。
不要把选集中的其他作者段落归给主作者，不要把机器译文清除乱码后直接当作可靠译文，不要给史料缺口编造舞名、商品、年代或地名。
中文卡片使用自然第二人称；原文引句另行标注，不改变其叙述视角。卡片完成后仍需资料编辑与文化审阅人签署。
```

## 交付门槛

每次写作或改写必须同时提交：

1. 源文和译文文件的当前 SHA-256 前 12 位；
2. 覆盖的 key 或书籍段落 ID；
3. effects 与结果句逐项对照；
4. 术语、来源和敏感内容的人工判断；
5. 审阅人、日期、结论和回归路径。

机器检查只能证明键、格式、引用和效果结构可解析，不能代替语言自然度、历史语境、文化表达或音画体验的人工签署。
