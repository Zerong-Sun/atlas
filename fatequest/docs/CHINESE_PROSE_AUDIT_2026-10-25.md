# 中文剧情文本问题清单与修订记录（2026-10-25）

## 审阅范围

以 `content/story/**/zh.md` 为中文源文，遍历 142 个文件、4,695 个文本键；同时检查城市入场结果、后续事件、纪念贴纸、图鉴传说与玩法文本。修订直接写入源文，再由 `story.mjs` 同步到 `content/i18n/zh.json`。中文键的全量检索是机械筛查；文风是否自然仍须在游戏里继续读屏检验。

## 问题清单

| 问题 | 表现与例子 | 修订标准 | 本轮处理 |
| --- | --- | --- | --- |
| 玩家选项像谜语 | “不把这话带走”听不出玩家到底拒绝了什么 | 直接说“不问水路了”“我还有别的安排”或“以后再说”，与结果一致 | 报达水路选项改成明确暂缓，船夫直接回应涨水风险 |
| 抽象比喻遮住信息 | “账本把远路上的货连到同一张桌上” | 写货名、货主、欠账、凭据和丢失的实际风险 | 报达商人的账本写明丝绸、胡椒、珍珠和赊欠对象 |
| 形容词不准确 | “这故事听着太狠” | 对战乱用“惨烈”等与事件相称的词，并让人物说得自然 | 说书人改用“听着太惨烈了？”引出两个版本 |
| 只报故事题目 | “他说起金塔、宝物和底格里斯河”却没有讲发生什么 | 玩家选择听故事后，要交代人物、事件、冲突、细节和不同证词 | 报达金顶与宝箱故事、河门与北门两家逃路、喀什噶尔七眠人两个版本均补出内容 |
| 遗物与传闻因果不明 | 祖父从灰中捡到钱币，却把它当作城破故事的凭据 | 分清物件来源、转述者所知与不能证明之事 | 钱币写成祖父的旧物和个人纪念，明确不知道原主是谁 |
| 讲方法却没有方法 | “教认纹样”“解释仪式”“介绍皮货” | 给出可复述的物件、步骤或判断依据 | 报达织金纹样、葬仪物件、北方皮货、竹宫拆装与马匹挑选均补具体内容 |
| 选择结果只复述操作 | “你逛了集市”“你歇脚打听一圈”“穿城而过” | 结果写玩家当场听到或遇到的内容；不另添系统状态 | 批量改写城市入场短结果，给出人物回应、船期、货物或行路细节 |
| 地点与选项矛盾 | 玩家已在城中，结果却“问清去本城的路” | 对照所在城市与路线目的地，结果指向真正下一站 | 安条克、备鲁亚、以弗所、阿卡、卡法、尼西亚等城市修正同城问路 |
| 句子残缺或引号错误 | “眼前这幅城景。”“你把这笔交易。”；诗歌引号不配对 | 逐键检查句子是否说完，引号是否成对 | 大不里士、埃舍尔结果补全；天德军歌谣和襄阳围城对白重新整理 |
| 玩法状态挤进故事 | “已标完”“收入行囊”“见闻记好” | 由界面展示记录、物品、时间；正文只写现场内容 | 全文扫描此类措辞并沿用第 5.0 节规则；本轮重点修订结果里的空泛收尾 |
| 传说被写成制作说明 | 图鉴内出现“本作只作传说收录” | 让传闻由人物、书信或旅人说出，保留讲述立场 | 祭司约翰条目改为信件传抄与旅人追问 |

## 修订覆盖点

- 报达主线：账本、围城说书、钱币来历、织金与历算、水路选择。
- 城市入场：大量一行式“路过／歇脚”结果改成当场对话；复核了已在城中却问去本城的结果。
- 后续故事：喀什噶尔七眠人、上都竹宫与驯马、伊本·法德兰路上的葬仪和皮货、各地工艺与行路片段。
- 纪念贴纸和图鉴：罗卜玉石、行在运河与西湖、襄阳城墙、怯失迷儿传闻、报达旧宫、祭司约翰传说。
- 文案规范：在 `TEXT_REQUIREMENTS.md` §5.0.1 加入直白选项、具体内容、因果校对和城市场景结果的检查项。

## 验收方法

1. `node tools/lore/story.mjs stamp zh && node tools/lore/story.mjs build && node tools/lore/story.mjs check`：确保中文源文进入游戏字典、无陈旧或缺失键。
2. 逐键扫描中文源文的未配对引号、结果中的空泛叙述和同城问路；对命中项人工判断，避免机械替换正常对白。
3. `git diff --check -- content/story docs/TEXT_REQUIREMENTS.md content/i18n/zh.json`：检查本轮文本格式。
4. Godot 无界面剧情／导航冒烟测试：确认事件加载和选择流程正常。
