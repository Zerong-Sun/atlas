# FateQuest 游戏测试标准与基线审阅

**版本：2026-10-20 · Godot 4.7.1 · 适用项目：FateQuest**

这套标准把“能启动”与“玩家能完成一段旅程”分开验收。它参考了 [ISTQB CT-GaMe 游戏测试大纲](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CT_GaMe_Syllabus_v1.0.1_LtrKuyi.pdf) 的游戏机制、图形、声音、关卡、控制器和本地化维度；单元/集成测试分层参考 [GUT 的 Godot 测试组织方式](https://github.com/bitwes/gut/blob/main/documentation/docs/Quick-Start.md)；运行期问题使用 Godot [Debugger/Profiler](https://docs.godotengine.org/en/stable/tutorials/scripting/debug/debugger_panel.html) 复核。项目继续使用现有的无第三方依赖 Godot 测试脚本，不把引入测试插件当成通过标准。

## 验收层级

| 层级 | 目标 | 证据 | 失败出口 |
|---|---|---|---|
| L0 静态完整性 | 表、资源、翻译、来源可加载 | `validate.mjs`、文本/素材审计、来源 hash | P0：无法加载、缺关键资源或缺文本 |
| L1 单元与状态机 | 钱、路线、事件、存档、队列状态正确 | `tests/run_tests.gd` 与核心测试 | P0：状态不可恢复、重复结算、错误数据写入 |
| L2 集成冒烟 | 从开局到入城、选择、后果、市集、出发、抵达可走通 | `smoke_*.gd`、固定 seed、按钮驱动 | P0：黑屏、卡死、无继续/返回、无法离城 |
| L3 探索试玩 | 用真实窗口、长文本、中文/英文、大字号、暂停/读档复现 | `PLAYTEST_FEEDBACK.md`、截图和日志 | P1：可绕过但误导、布局遮挡、听觉/视觉缺失 |
| L4 非功能 | 声音分层、性能、兼容性、本地化和来源边界 | 音频门禁、Godot Profiler、双语报告 | P1/P2：帧率、声音入口、语言或来源证据不足 |

## 六项统一检查

1. **需求完整性**：开局、身份、入城、事件、后果、城市探索、市集、出发、途中事件、抵达、存档、死亡/结局都必须有可执行测试。
2. **逻辑正确性**：每次选择最多结算一次；结果页可继续；队列和 active event 能清空；金钱、货物、路线和日期同步。
3. **边界情况**：零钱、满货、季节关闭、无路、缺事件、重复一次性事件、重复点击、暂停读档、语言切换、大字号和低动效都要有覆盖。
4. **代码质量**：测试必须有 watchdog，失败必须返回非零；不得以等待超时代替继续；测试数据与生产数据分离，不能破坏玩家偏好。
5. **覆盖率**：单元覆盖核心规则，集成覆盖至少一条完整旅程，按钮驱动覆盖真实可见控件；探索试玩补充自动化无法证明的声音和历史文化判断。
6. **实际运行**：每次候选必须在 Godot headless 跑逻辑和在真实窗口检查入口；声音至少验证入口、切换、静音、音量和资源加载。

## 断点/卡点契约

任何可见事件必须满足以下之一：

- 可见且可点击的选择带 `resultText`、`queue_event`、占卜结果或明确状态反馈；
- 结果页有唯一的继续/返回出口；
- 城市界面有进入探索、市集、行囊、出发或返回地图的出口；
- 旅途界面有等待、处理中途事件、取消计划或抵达出口；
- 读档后能恢复到以上某个可操作状态。

测试不能只调用 `_resolve_choice()` 这种内部函数；至少一条关键路径必须通过真实按钮找到并触发。发现卡点时记录固定 seed、事件 ID、步骤、预期、实际、日志和截图。

## 2026-10-20 基线结果

- 45 个 `smoke_*.gd` 中，44 个通过；欢迎旅程的实际按钮链也通过，但“新安装没有 `ui.cfg`”检查因前序测试污染用户偏好而失败。这是测试隔离缺陷，已列为 P1 修复，不应算作玩家流程失败。
- `run_tests.gd`、`smoke_audio_runtime.gd`、`smoke_review_edges.gd` 通过；预期的非法输入错误日志不会计为失败。
- 当前没有开局/标题专用音乐入口。`AudioDirector` 只在 `_begin()` 后由 `set_place()` / `set_travel()` 启动文化层，因此标题页和抽取身份阶段没有独立主题。这列为 P1，修复为单独的程序化世俗开场主题，并在开始旅程时淡出。
- 现有 G29 结果页门禁有效，但缺少统一的城市出口、事件出口和声音入口契约测试。本轮补充 `smoke_gameplay_contracts.gd` 与开局主题检查。

## 运行命令

```bash
cd fatequest
node tools/validate/validate.mjs --quiet
godot --headless --path . --script tests/run_tests.gd
for t in tests/smoke_*.gd; do godot --headless --path . --script "$t" || exit 1; done
godot --headless --path . --script tests/smoke_gameplay_contracts.gd
```

自动测试通过不等于声音历史适切性或全城市人工试玩签署；这两项仍需保留人工记录。

## 修复后回归结果

- 欢迎旅程的 `ui.cfg` 已在测试内部隔离并在退出时恢复；因此完整的 46 个 `smoke_*.gd` 可以串行运行，不会把前一个测试的用户偏好带入“新安装”断言。网络地图探针在 headless 批量运行中明确跳过，需用真实窗口单独验收。
- 新增 `smoke_gameplay_contracts.gd`：生产内容库加载 1,467 条记录，检查 1,074 个事件选项、103 座城市和 206 条路线；所有可见选项都有结果/占卜/队列反馈，所有城市都有地图出口，所有队伍路线指向有效城市并提供交通方式。
- 新增独立开场主题 `assets/audio/intro/title_theme.wav`。欢迎书桌启动它；确认身份或读档时淡出；抵达城市后继续使用原有文化与场景混音。音频冒烟测试验证资源、启动、停止和已有场景切换。
- 原网络地图探针在离线 headless 批量中会把 CDN 不可用误报为玩法失败；现在明确标记为图形/网络 opt-in。真实窗口运行已实测 `loaded=12`、归属标识可见、输入层可用、`1280×720`，结果通过。
- 本轮自动回归范围：静态验证、核心测试、完整 smoke 串行、音频运行时、游戏流程契约。真实设备的音量/循环听审、全城市探索试玩和历史文化敏感读者审阅仍属于 L3/L4 人工签署项。
