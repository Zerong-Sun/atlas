# 开局人物选择：六方面验收与修复清单（2026-11-04）

## 验收范围

开局书案 → 随机年代的三位人物 → 选择或重抽 → 创建世界 → 存档恢复。角色库以身份为选项，姓名按出身与信仰从 20 个双语名字中抽取；同一轮不重复姓名、身份或出身。

## 修复清单

| 编号 | 发现的问题 | 修复 | 验证 |
| --- | --- | --- | --- |
| F1 | 角色或姓名数据不足时，生成器可能返回一两张卡，界面却仍写“三位旅人”。 | 先筛选能提供三种出身的年代；不足三人时返回空结果，界面只接受完整的三人名单。 | 单元测试覆盖不足角色、不足姓名、混合可用与不可用年代。 |
| F2 | 旧卡片只凭候选 ID 校验；若重抽后 ID 碰撞，旧按钮仍可能触发选择。 | 每张接受按钮绑定抽取轮次；只接受当前轮次的卡片。 | 烟测人为制造相同 ID 后点击旧卡，世界状态保持为空。 |
| F3 | 身份选择前没有显示该人物的远行目标与随身物，影响对不同开局的判断。 | 在人物卡上显示目标城市及目标类型；有起始物品时列出物品。 | 中英界面烟测核对卡片内容与候选数据。 |
| F4 | “重抽年代”暗示下一轮必换年代，但随机结果允许再次抽中同一年份。 | 按钮改为“再抽三位旅人”，年代仍由每轮随机决定。 | 文案与生成逻辑对照。 |
| F5 | 旧的直接创建身份按钮函数已无入口，可能绕过三选一。 | 删除未使用的 `_archetype_button`。 | 搜索调用点并运行开局烟测。 |
| F6 | 设计文档仍描述导入过场及生辰、文化、信仰的分层手选流程，与现行界面冲突。 | 将 §3–4 重写为实际的书案、三选一和旅程创建流程；尚未实现的年代效果标为规划。 | 文档逐项对照生成器、界面与存档代码。 |

## 六方面核对

| 方面 | 验收结果 |
| --- | --- |
| 需求完整性 | 不再提供年代选择；每轮只出现同一随机年代的三位人物。卡片以姓名和身份为主，并提供出身、信仰、年龄、起点、目标、资金、语言、物品、命格和执念。20 个名字在中英文本中各不重复。 |
| 逻辑正确性 | 身份限定可用年代；姓名与身份的出身、信仰匹配；选择的日期、出生日期、资金、语言、信仰、命格与游戏状态一致，姓名和年代可随存档恢复。 |
| 边界情况 | 空库、角色不足、姓名不足、不可用年代不会产生部分名单；返回书案和连续重抽后，旧卡片不能创建旅程。 |
| 代码质量 | 候选生成为纯数据快照，界面直接使用快照；删除失效入口；生成接口要求显式传入名字。 |
| 测试覆盖 | 单元测试检查 100 个种子、所有年代、双语姓名、去重和数据不足；界面烟测覆盖三个选择按钮、重抽、返回、布局、持久化。 |
| 实际运行 | 使用隔离 `user://` 启动 Godot 4.7.1；中英双语、960×640 与 1280×720、大字号的真实窗口检查通过；游戏启动通过。 |
